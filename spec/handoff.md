# Relai handoff format — v0.5

> Status: draft (2026-11-03). The reference implementation is `relai handoff`
> ([`internal/handoff`](../internal/handoff)). Evidence for the rules below:
> [`eval/README.md`](../eval/README.md) (experiment E2).

The key words MUST, SHOULD and MAY are used as in RFC 2119.

## 1. Purpose

A handoff tells someone who arrives cold — a person or an AI agent — **where the work stands and
what to do next**, in a few hundred tokens, so they do not re-read the history. It is loaded at
the start of every session (level L1, after `AGENTS.md`); everything else is loaded on demand.

## 2. Principles

1. **Deterministic.** A handoff is built from structured sources only (git, the task backend, the
   spec backend, the curated notes, the project's harness files). No LLM writes it. The same repo
   state MUST give the same handoff.
2. **Budgeted.** A handoff MUST fit its token budget (default 2,000). The budget is met by showing
   fewer list items, never by rewording.
3. **Pointers, not copies.** Each section ends with the command or path that gives the details
   (`bd show <id>`, `openspec show <name>`, a file path). The handoff is an index, not a summary.
4. **Absence is information.** Every section is always present. When a source is missing, the
   section says so in one line, so the reader does not go looking for it.
5. **Contradictions are surfaced, not resolved.** When sources disagree (a task is open but a
   commit says it is done), the handoff shows both and says "check first". E2 showed that a compact
   handoff that is confidently wrong is worse than no handoff: a small model trusted a stale task
   list and stopped after one turn with the wrong answer.

## 3. Sources

| Source | Read with | Used in |
|---|---|---|
| git | `git branch`, `git log -20`, `git status --short` | State |
| Task backend: Beads | `bd ready --json`, `bd list --status in_progress --json`, `bd blocked --json` | Tasks |
| Spec backend: OpenSpec | `openspec list --json`, each change's `tasks.md` | Active changes |
| Curated notes | `.relai/notes.md` | Decisions and pitfalls |
| Harness | files found by `relai discover` | Harness |

Other backends (GitHub Issues, Spec Kit…) plug in as adapters and fill the same sections. A
source that is absent, or whose tool is not installed, is reported as absent.

## 4. Structure

A handoff is a Markdown document with these parts, in this order.

### 4.1 Title and format line

```
# Handoff — <repo directory name>

Generated by `relai handoff` (format v0.5). Read this first; load anything else on demand.
```

The format line MUST carry the format version. In degraded mode (§4.7) it MUST also say so, e.g.
`(format v0.5, degraded mode — no AGENTS.md/CLAUDE.md, OpenSpec, or Beads found)`.

### 4.2 `## State`

- One line: branch, short HEAD hash and commit date, number of uncommitted files.
- Up to 5 uncommitted paths, then `… (N more)`.
- `Recent commits:` — one line each, `<hash> <date> <subject>`, newest first, subjects cut at
  110 characters. Default 8 commits.
- Optionally one `Team signals:` line, after the commits and only when at least two of these
  three signals of parallel work are present: two or more `owners` in `relai.yaml`; two or more
  distinct assignees on in-progress tasks; two or more distinct commit authors in the last 14
  days. It names the signals that fired and points to relai-team
  (https://github.com/ECG-Rudy-Glt/RELAI-TEAM), the optional team layer. It is advice, not state:
  a reader MAY ignore it, and it is absent for solo work.

### 4.3 `## Tasks`

In degraded mode (§4.7), this section is omitted entirely — not even the placeholder below.

Without a task backend: `(no task graph in this repo)`, plus the adapter that would add one.

With a task backend whose tasks **cannot be read here** (Beads' `.beads/` exists but the `bd` command is
missing, or this clone has no database yet, or `bd` fails): one line, `Tasks cannot be read here: <reason>.
Fresh clone? Run `bd bootstrap --yes` to load them from `.beads/issues.jsonl`.`, where the reason is one of
a short fixed set and never raw tool output. If `.beads/issues.jsonl` is present, it is followed by that
snapshot (unfinished, non-epic tasks only: *In progress*, then *Open (N total)*, most urgent first), labelled
as a snapshot that may lag. The handoff MUST NOT print an empty *Ready* list in this case: "0 ready" would
read as "nothing to do".

With one, in this order, each list omitted when empty except *Ready*:

1. **Check first** — open tasks (in progress, ready or blocked) whose ID appears as a whole word in
   one of the recent commit subjects, with that commit. At most 5. These are often finished work
   that nobody closed.
2. **In progress** — ID, priority, title.
3. **Ready (unblocked, N total)** — ID, priority, title, in the backend's order (priority first).
4. **Blocked (N total)** — ID, priority, title, `blocked by` the blocking IDs. A ready list alone
   hides the real next step when the blocker is stale (E2, fixture F4).
5. `Details: bd show <id>.`

### 4.4 `## Active changes (specs)`

In degraded mode (§4.7), this section is omitted entirely — not even the placeholder below.

Without a spec backend: `(no OpenSpec changes in this repo)`. Otherwise one line per active change:
name, completed/total tasks, status, then an indented `next:` line with the first unchecked task of
its `tasks.md`. Without the `next:` line agents explored the code to find it (E2, fixture F2:
3 turns → 1). Ends with `Details: openspec show <name>.`

### 4.5 `## Harness`

What the project already gives agents, so the reader uses it instead of reinventing it. One line per
kind present, names only, with where they live:

```
- Instructions: AGENTS.md, CLAUDE.md
- Skills (.claude/skills): deploy-playbook, homelab-tour
- Commands (.claude/commands): /opsx:apply, /opsx:propose
- Hooks (.claude/settings.json): PreToolUse, SessionStart
- MCP servers (.mcp.json): homelab
- Docs to read on demand: docs/HANDOFF.md, Documentation/journal/
- CI: .github/workflows/ci.yml
```

Kinds with nothing found are omitted; if nothing is found at all: `(no agent harness found)`.
Full inventory: `relai discover`.

### 4.6 `## Decisions and pitfalls`

The content of `.relai/notes.md`, verbatim. Without the file:
`(no .relai/notes.md yet — run relai discover --prompt to draft it)`.

`notes.md` is curated by people (an agent MAY draft it, a person reviews it). Recommended
sections, one line per entry:

- `### Next` — only when the next step is not in a task backend (E2, fixture F3);
- `### Decisions` — `date — decision — why`;
- `### Pitfalls` — `symptom → cause → what to do`.

### 4.7 Degraded mode

Relai's value SHOULD NOT require a team to adopt the rest of the composed ecosystem first. The
system SHALL run in degraded mode when `AGENTS.md`/`CLAUDE.md`, an OpenSpec `openspec/` directory,
and a Beads `.beads/` directory are all absent (the same "harness present?" check `relai discover`
already does), instead of producing an empty or near-empty report.

In degraded mode:

- The format line (§4.1) states it is degraded mode.
- `## State` (§4.2) is unchanged: same content and format as full mode, from git alone.
- `## Tasks` (§4.3) and `## Active changes` (§4.4) are omitted entirely: degraded mode MUST NOT
  infer, summarize, or guess at tasks, decisions, or pitfalls — it only reports what it can read
  directly from git and the working tree.
- Two sections replace them, in this order:

  ```
  ## Recently touched files (last 7 days)
  - `path/to/file.go`
  … (N more)                              (when truncated)
  (none)                                  (when nothing was touched)

  ## Open markers (TODO/FIXME)
  - `path/to/file.go:12:// TODO: handle retries`
  … (N more)                              (when truncated)
  (none found)                            (when no markers exist)
  ```

  Recently touched files come from `git log --since=7.days --name-only`; markers come from
  `git grep -n -I -E "TODO|FIXME"` over tracked files. Both are bounded by the same token budget
  as the rest of the handoff (§5); when both would exceed it, the longer list is truncated first.
- `## Harness` (§4.5) and `## Decisions and pitfalls` (§4.6) behave exactly as in full mode (both
  are typically empty placeholders in degraded mode, since there is no harness or notes yet, but
  the sections themselves are not special-cased).

## 5. Budget

- Token count is estimated as `ceil(characters / 4)`; it is model-agnostic and slightly
  pessimistic for English.
- Default budget 2,000 tokens; MAY be changed by the caller (`--max-tokens`).
- When over budget, cut in this order, one item at a time, re-checking after each cut:
  0. the `Team signals:` line (§4.2), before anything else;
  1. task lists (in progress, ready, blocked) down to 3 items each;
  2. recent commits down to 3;
  3. harness lines, from the last;
  4. in degraded mode only: the longer of recently-touched-files / open-markers (§4.7), one at a
     time, until both are empty;
  5. notes, from the end, replaced by `… (N more lines in .relai/notes.md)`.
- *Check first* lines and the `next:` line of active changes are never cut: they carry the
  contradictions and the next step.
- Counts (`N total`) always show the full number, so the reader knows what was cut.

## 6. Determinism and safety

- No timestamps other than commit dates; no random order: lists follow the backend's order or the
  file system's sorted order.
- No secrets: the handoff only quotes commit subjects, task titles, file names and `notes.md`.
  Anything sensitive in those is already in the repo.
- Producing a handoff MUST NOT modify the repository.

## 7. Versioning

- `vMAJOR.MINOR`. A new section or a new line kind is a minor change; renaming or removing a
  heading, or changing the meaning of a line, is a major change.
- Consumers SHOULD rely on the `##` headings, not on line order inside a section.

## 8. Conformance

An implementation conforms if, on the fixtures in `eval/fixtures/`, it produces every section of
§4 in order, stays within budget, and lists the *Check first*, *Blocked* and `next:` lines that the
reference implementation lists. The E2 harness (`go run ./eval/e2`) measures whether the result is
good enough for agents.

## Changelog

- v0.5 (2026-11-04) — the handoff is still read-only in practice: git runs with `--no-optional-locks` so
  `.git/index` is never rewritten (§6); control characters (ESC, BEL…) are stripped from every line,
  non-ASCII file names are printed as they are; `bd` output that is not the JSON asked for counts as
  "cannot be read" (§4.3); with `openspec/` present but the tool missing or failing, the handoff says so
  and lists the changes read from `openspec/changes/*/tasks.md` (§4.4); the changes list is capped like the
  task lists, with "… (N more changes)", so many active changes cannot break the budget (§5). The cut of
  each list is found by bisection, not one item at a time (same output, no minutes-long runs on big repos).
- v0.4 (2026-11-03) — `## Tasks` says when the tasks cannot be read here (fresh clone, no `bd`, `bd` failing)
  and falls back to the snapshot in `.beads/issues.jsonl` (§4.3), instead of printing "Ready: 0".
- v0.3 (2026-11-03) — `Team signals:` line in `## State` (§4.2), shown only with two signals of
  parallel work; first item cut under budget (§5).
- v0.2 (2026-11-03) — degraded mode (§4.7): a git-only report, with recently-touched-files and
  TODO/FIXME sections, when no AGENTS.md/CLAUDE.md, OpenSpec, or Beads is present.
- v0.1 (2026-11-03) — first version, from the CLI output and E2: format line, *Check first*,
  *Blocked*, `next:` per change, *Harness*.
